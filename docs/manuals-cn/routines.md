# 定时例程

在**设置 > 定时例程**中配置无人值守的 Pi 工作。Pi Cloud 服务器须保持运行，浏览器可以关闭。

1. 新增例程，填写名称和指令。
2. 选择允许根目录内的项目目录、智能体配置及模型。
3. 选择**单次**、**固定间隔**或**每日**。首次执行日期按浏览器本地时间输入；每日执行时间按服务器本地时间计算，面板会显示该时间基准。最小间隔为五分钟。
4. 设置 1 至 120 分钟的超时，默认为 30 分钟。
5. 可选共享企微群机器人通知渠道。在**设置 > 模型窗口启动**中配置渠道。
6. 保存。新例程默认停用。准备好授权无人值守执行时，启用并保存。**立即执行**也可以为停用的例程创建手动运行。

例程复用现有 Pi 工具、提供商凭据和记忆。启用即授权指令按现有工具权限执行命令及修改文件；此功能不提供只读沙箱或敏感操作审批门禁。建议使用独立项目目录。该目录中存在正在执行的 Pi 会话时，调度器会等待，但不会阻止其他交互会话稍后开始。

## 执行与历史

调度器每分钟检查一次，同一时间执行一个例程。每次运行创建独立的持久会话。历史记录显示状态、时间、会话 ID、摘要/错误及通知投递状态，支持分页。完整对话保留在现有 Pi 会话存储中。

固定间隔按首次执行时间计算。停机后最多补一次过期执行，不逐个回放所有错过的间隔。单次计划只消费一次。执行失败不自动重试，因为工具可能已经修改文件或外部系统；需要另行尝试时使用**立即执行**。

停用会取消已排队的计划执行，不会停止正在运行的执行。编辑会取消旧配置中已排队的计划执行；正在运行的任务保留原始配置。删除前须取消排队及执行中的任务，删除后仍保留运行历史。

取消或超时会请求 Pi 智能体停止，执行实际结束前仍占用工作槽位。这是协作式取消，无法保证终止已脱离会话的子进程。服务器重启会将此前执行中的任务标记为**已中断**，不会自动重跑。排队任务会继续保留。

## 企微结果投递

执行结果与通知独立持久化。通知失败不会重新执行指令。最多发送四次，重试间隔分别为一、五、三十分钟。重试耗尽后可点击**重试通知**，重新开始投递尝试。渠道被删除时会显示投递失败。

通知包含运行 ID 和截短的结果。采用至少一次投递：企微已收到消息但 Pi Cloud 尚未记录成功时发生崩溃，可能产生重复消息。

无需新增环境变量，沿用现有身份验证及允许根目录配置。调度器支持每个数据库运行一个 Pi Cloud 服务进程，请勿让多个调度实例共用同一数据库。
