# Memory 系统用户手册

Memory 系统用于让 Pi Cloud 记住“长期有效”的信息，并在后续对话中自动提供给模型。它适合保存项目约定、用户偏好、已经确认的事实、决策和踩坑记录，避免每次新会话都重复说明背景。

## 它有什么用

- **跨会话延续上下文**：新会话也能知道项目规则、历史决策和重要事实。
- **减少重复提示**：常用偏好或项目约定可以被固定召回。
- **沉淀项目知识**：把对话中确认过的信息整理成可搜索、可编辑的知识条目。
- **辅助团队/长期任务**：同一项目下的托管 worktree 会共享项目级记忆。
- **保留来源**：自动提取的记忆会记录来源会话和证据，方便回溯。

## 记忆的类型

### 作用域

- **Project（项目级）**：只对当前项目生效。适合项目规范、架构决策、已知坑点等。
- **Global（全局级）**：在同一个 Agent Profile 下的所有项目生效。适合跨项目的用户偏好或规则。

> 注意：自动提取出的全局记忆默认进入 Review 队列，需要人工批准后才会生效。

### 分类

- **rule**：必须遵守的规则。
- **preference**：用户偏好。
- **decision**：已经做出的决策。
- **fact**：已确认事实。
- **pitfall**：踩坑、限制或注意事项。

### 状态

- **active**：已生效，会参与搜索和自动召回。
- **pending**：待审核，通常是自动提取出的全局记忆。
- **archived**：已归档，不再参与召回。

## 如何使用

### 配置自动提取

自动提取记忆默认关闭。打开 Settings，在 **Auto-extract memory** 设置中启用后，系统会在助手回合完成时自动提取长期记忆候选；该设置会持久化保存。也可以随时在同一位置关闭自动提取。

### 打开 Memory Center

在侧边栏底部点击 **Memory** 按钮打开 Memory Center。顶部会显示当前 Agent Profile 和项目路径。

Memory Center 中有三个标签页：

- **Project**：查看当前项目级 active 记忆。
- **Global**：查看当前 Profile 下的全局 active 记忆。
- **Review**：审核待批准的全局记忆。

可以通过搜索框、Category 和 State 过滤记忆。

### 手动新增记忆

1. 打开 Memory Center。
2. 点击 **Add memory**。
3. 输入一条简短、原子化、长期有效的内容。
4. 选择分类、填写标签。
5. 可选择 **Pin for recall**。固定记忆默认仅在匹配当前 Prompt 时适用，避免在无关对话轮次中注入规则。只有真正全局适用的指令才应设为**始终适用**。
6. 点击 **Save memory**。

建议写法：

- 好：`本项目的移动端任务队列入口放在导航栏下拉菜单中。`
- 不好：`今天我修了一些东西。`

### 编辑、固定、归档、恢复和删除

在记忆行右侧可以：

- 点击铅笔图标编辑内容、分类、标签、固定状态或固定适用方式。
- 点击图钉图标固定/取消固定。
- 归档 active 记忆，使其不再参与召回。
- 将 archived 记忆恢复为 active 状态。
- 永久删除记忆。

系统使用 `revision` 做并发保护：如果某条记忆在你操作前已被修改，会提示冲突，避免覆盖别人或后台的更新。

### 整理记忆

在 **Project** 和 **Global** 标签页中点击 **Tidy up**，可以检查重复或陈旧且相互矛盾的 active 记忆。Pi Cloud 会建议保留和归档哪些条目，但只有在你选中建议并确认 **Archive selected** 后才会更改记忆。

### 审核自动提取的全局记忆

自动提取出的全局规则/偏好会进入 **Review**：

- **Approve**：批准并生效。
- **Edit & approve**：修改后批准。
- **Reject**：拒绝并归档。

审核时可以查看 evidence（证据），确认这条记忆确实来自对话内容。

### 从当前会话提取记忆

在有当前会话时，Memory Center 顶部会出现 **Extract current session**。点击后，系统会把该会话加入提取队列，并从对话中生成候选记忆。

适用场景：

- 你刚完成一段重要讨论，希望把结论沉淀下来。
- 之前的自动提取没有覆盖某些信息。
- 需要从历史会话导入记忆。

### 在对话中让 Agent 操作记忆

Agent 内置了 `memory` 工具。你可以直接要求：

- “记住：本项目的 API 错误格式必须包含 code 和 message。”
- “搜索一下你记得的移动端任务队列规则。”
- “更新这条记忆……”
- “忘记这条记忆……”

约束：只有当用户明确要求记住、更新或忘记时，Agent 才应主动修改记忆；普通对话中的学习由后台自动提取负责。

## 实现原理

### 总体流程

Memory 系统由三部分组成：

1. **前端 Memory Center**：展示、筛选、编辑、审核记忆。
2. **后端 Memory Runtime**：负责项目解析、记忆服务、自动提取队列和 WebSocket 通知。
3. **SQLite 存储**：保存项目、记忆、提取任务，并用 FTS5 支持全文搜索。

简化流程：

```text
用户对话 / 手动操作
        ↓
WebUI 后端 MemoryService
        ↓
MemoryStore 写入 SQLite
        ↓
后续请求前自动召回相关记忆
        ↓
作为 system prompt 的一部分提供给模型
```

### 项目和 Profile 隔离

每条记忆都属于某个 **Agent Profile**。项目级记忆还会绑定到一个规范化后的项目路径。

项目路径解析时会：

- 优先使用 worktree 的 base repo path，使同一基础项目的托管 worktree 共享项目记忆。
- 对路径做 `realpath` 规范化。
- 按 `profileId + canonicalPath` 创建或复用 memory project。

因此，不同 Profile 的记忆互相隔离；同一 Profile 下，全局记忆跨项目可用，项目记忆只在对应项目可用。

### 自动召回

每次 Agent 开始回答前，Memory 扩展会：

1. 解析当前 Profile 和项目上下文。
2. 取出 pinned 的 active `rule` / `preference` 作为“指令型记忆”。
3. 根据用户当前 prompt 做全文搜索，找出相关的 active `fact` / `decision` / `pitfall`。
4. 按 token 预算裁剪后，注入到 system prompt 中。

默认的自适应词法策略会综合 Prompt 意图、词法相关性、作用域、时效性和历史效用进行评分，移除冗余结果，并从 0、400、800、1,500 或 2,500 tokens 中动态选择总预算。设为**仅在匹配时适用**的固定记忆，只有相关性评分达到阈值才会加入上下文。设置 `PI_CLOUD_MEMORY_POLICY=legacy` 可回退到旧版策略；该策略分别为固定记忆和相关参考记忆提供约 2,000 tokens 的预算，并且最多召回 8 条参考记忆。

注入格式会区分：

- **remembered-instructions**：直接用户规则/偏好，模型应遵守，除非当前请求覆盖。
- **remembered-reference**：参考数据，不是指令，不能把其中内容当命令执行。

### 自动提取

Agent 回答结束后，Memory 扩展会把从上次基线到当前 leaf 的会话片段加入提取队列。后台提取器会：

1. 读取会话分支内容。
2. 构造提取提示词，要求模型只返回严格 JSON。
3. 给模型提供已有相关记忆，便于判断 `new`、`duplicate` 或 `replace`。
4. 校验候选项：作用域、分类、证据、长度、敏感信息、全局记忆限制等。
5. 应用候选项：
   - project 候选直接变成 active。
   - global 候选变成 pending，等待 Review。
   - replace 会保留 supersedes 关系，便于追踪替换历史。

自动提取最多尝试两次。服务器重启或前台请求打断时，运行中的任务会重新排队。失败的任务会显示在 Memory Center 中，并提供 **Retry** 和 **Clear** 操作。

### 存储结构

核心表包括：

- `memory_projects`：Profile 下的项目路径。
- `memories`：记忆内容、分类、作用域、状态、来源、标签、证据、版本等。
- `memory_extraction_runs`：自动/手动会话导入的提取任务。
- `memory_fts`：SQLite FTS5 全文索引。

系统会用内容 hash 防止同一作用域中出现重复的 active/pending 记忆。内容和标签变更会通过触发器同步到 FTS 索引。

### 安全与质量控制

- 记忆内容会被规范化：去首尾空白、压缩空白字符。
- 单条内容最长 2000 字符。
- 标签最多 10 个，每个最多 32 字符，并会转成小写去重。
- 使用自适应提取策略时，每次最多生成 8 个候选项；在执行常规记忆验证前，每个候选项最多 220 个字符、4 个标签，每个标签最多 24 个字符。
- 会拒绝明显的密钥、token、密码等敏感内容。
- 自动提取要求证据必须来自原对话；rule/preference 必须有用户发言作为证据。
- 全局自动记忆只允许 rule/preference，并且需要人工审核。

## 使用建议

- 只保存长期有效、可复用的信息。
- 一条记忆只表达一个事实或规则。
- 对强约束使用 `rule`，对习惯倾向使用 `preference`。
- 对容易误导模型的旧信息及时归档。
- pinned 适合少量非常重要的规则/偏好，不要把所有内容都 pin。
- Review 时优先检查 evidence，避免把模型猜测保存成事实。

## 常见问题

### 为什么我刚说过的内容没有立即成为记忆？

自动提取在 Agent 回答结束后异步运行，并且会过滤短期任务进度、猜测、日志、代码片段和敏感信息。全局候选还需要审核。

### 为什么全局记忆在 Review 中？

全局记忆会影响同一 Profile 下所有项目。为避免误污染，自动提取出的全局记忆默认 pending，需要人工批准。

### 为什么 pinned 记忆提示超出预算？

pinned 规则/偏好有召回 token 预算。如果固定的内容过多或过长，系统会提示 overflow。请取消固定不重要的条目，或把内容缩短。

### 归档和删除有什么区别？

归档后的记忆不再参与召回，但仍保留在历史记录中，并且可以恢复。删除会永久移除记忆；如果以后可能需要查看其来源或替换历史，请使用归档。
